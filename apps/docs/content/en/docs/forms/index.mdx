# Forms

Forms in Zormy are built with **react-hook-form** (via `useForm`) and the **resolver** `zormyResolver`, which builds the Zod schema from the fields and integrates it with validation.

## Basic flow

1. Define the **fields** with `field("key").schema(...).render(...)` (see [Fields](/docs/fields)).
2. Use **`<Form fields={[Field1, Field2, ...]} defaultValues? mode? onSubmit? />`** (Form uses useZormy internally) or create the form with `useZormy` / `useForm` and pass **`<Form methods={form}>`**.
3. Render the fields inside the Form.

## `zormyResolver({ fields })`

The resolver receives an **array of field components**. It:

- Builds the Zod schema (flat or nested based on dot keys)
- Supports dynamic schemas (function receiving `formValues`)
- Returns a resolver compatible with `useForm`

<Callout type="info">
	The `fields` array must contain **exactly** the fields that will be rendered in the form (or in
	the step, in the case of wizards). Also include fields used in `dependsOn` from other fields.
</Callout>

## `Form` Component

Form supports **two modes**: with **`methods`** (you pass the return value of `useForm`/`useZormy`) or with **`fields`** (you pass the array of fields and optionally `defaultValues`, `mode`, `onSubmit`; Form uses useZormy internally). In both cases it provides the context (FormProvider) and, by default, renders a `<form>`.

| Prop            | Type                   | Description                                                                                      |
| --------------- | ---------------------- | ------------------------------------------------------------------------------------------------ |
| `methods`       | `UseFormReturn`        | Instance returned by `useForm` or `useZormy` (when not using `fields`)                           |
| `fields`        | `FieldComponentBase[]` | Array of fields; Form uses useZormy internally (when not using `methods`)                        |
| `defaultValues` | object                 | Initial values (only with `fields`)                                                              |
| `mode`          | string                 | Validation mode: `"onChange"`, `"onBlur"`, `"onSubmit"`, etc. (only with `fields`)               |
| `onSubmit`      | `(data) => void`       | Callback with validated data on submit                                                           |
| `contextOnly`   | `boolean`              | If `true`, does not render `<form>`, only the context (useful for custom wrappers or Radix Slot) |
| `children`      | `ReactNode`            | Form content                                                                                     |

For **useForm vs useZormy vs createForm**, see [Hooks](/docs/forms/hooks).

## Validation mode (`mode`)

**When** fields are validated is defined by the `mode` option of `useForm` (and `useWizard`):

| Value         | Behavior                                                        |
| ------------- | --------------------------------------------------------------- |
| `"onChange"`  | Validates on every change (common default)                      |
| `"onBlur"`    | Validates when leaving the field                                |
| `"onSubmit"`  | Validates only on submit                                        |
| `"onTouched"` | Validates after the field is "touched" and then on every change |
| `"all"`       | Validates on onChange and onBlur                                |

## `defaultValues`

They must cover **all field keys** (including nested ones). Examples:

- Fields `"name"` and `"email"` → `defaultValues: { name: "", email: "" }`
- Field `"user.name"` → `defaultValues: { user: { name: "" } }`

For the complete API of `Form` and `zormyResolver`, see [API Reference](/docs/api-reference).
