# API Reference

Complete API reference for Zormy with practical examples and TypeScript types.

	API!
</Callout>

    ## Fields

    ### `field(key)`

    Creates a fluent builder to construct a form field.

    | Parameter | Type | Description |
    |-----------|------|------------|
    | `key` | `string` | Unique key that identifies the field in the form (e.g., `"name"`, `"user.email"`) |

    **Returns:** `FieldBuilder<Key>`

    **Example:**
    ```tsx
    const NameField = field("name")
      .schema(z.string())
      .render(({ register }) => <input {...register()} />);
    ```

    ### `abstractField()`

    Creates a builder for an abstract field (reusable template). Use `.extend({ key, schema?, render?, dependsOn?, props? })` to obtain a concrete field.

    **Returns:** `AbstractFieldBuilder`

    **Example:**
    ```tsx
    const BaseTextField = abstractField()
      .schema(z.string())
      .render(({ register }) => <input {...register()} />);

    const NameField = BaseTextField.extend({ key: "name" });
    const EmailField = BaseTextField.extend({ key: "email" });
    ```

    ### `useField<Key, Schema>(key)`

    Hook to access the form context with strong typing for a field. Must be used inside `FormProvider` or `<Form>`. Returns typed `register`, `fieldState`, `control`, `getValues`, `setValue`, and `watch` for the field.

    | Parameter | Type | Description |
    |-----------|------|------------|
    | `key` | `Key` | Field key (must match the field key in the form) |

    **Returns:** `UseFieldReturn<Key, Schema, DepsTypes>`

    ## Components

    ### `Form`

    Form component integrated with react-hook-form. Supports **two modes**:

    - **`methods`**: you pass the return value of `useForm` or `useZormy` (external control).
    - **`fields`**: you pass the array of fields; Form uses `useZormy` internally. Optionally pass `defaultValues`, `mode`, `onSubmit`, etc.

    | Property | Type | Required | Description |
    |-----------|------|----------|------------|
    | `methods` | `UseFormReturn<TFieldValues>` | * | useForm instance (required when not using `fields`) |
    | `fields` | `readonly FieldComponentBase[]` | * | Array of fields; Form uses useZormy internally (required when not using `methods`) |
    | `defaultValues` | `DeepPartial<FormValues>` | ❌ | Initial values (only with `fields`) |
    | `mode` | `"onChange"` \| `"onBlur"` \| `"onSubmit"` \| ... | ❌ | Validation mode (only with `fields`) |
    | `onSubmit` | `(data: FormValues) => void` | ❌ | Callback called with validated data on submit |
    | `contextOnly` | `boolean` | ❌ | If true, provides only context without wrapping in `<form>` |
    | `children` | `ReactNode` | ❌ | Form content |
    | `...formProps` | `ComponentPropsWithoutRef<"form">` | ❌ | `<form>` element props |

    **Example with `methods`:**
    ```tsx
    const form = useZormy({ fields: [NameField], defaultValues: { name: "" } });
    <Form methods={form} onSubmit={(data) => console.log(data)}>
      <NameField />
      <button type="submit">Submit</button>
    </Form>
    ```

    **Example with `fields` (Form creates the form internally):**
    ```tsx
    <Form
      fields={[NameField, EmailField]}
      defaultValues={{ name: "", email: "" }}
      mode="onChange"
      onSubmit={(data) => console.log(data)}
    >
      <NameField />
      <EmailField />
      <button type="submit">Submit</button>
    </Form>
    ```

    ### `useZormy({ fields, ...useFormOptions })`

    Hook that integrates an array of fields with react-hook-form’s `useForm`, automatically injecting the `zormyResolver`. Avoids manually passing `resolver` and preserves type inference from fields.

    | Property | Type | Required | Description |
    |-----------|------|----------|------------|
    | `fields` | `readonly FieldComponentBase[]` | ✅ | Array of field components |
    | `...useFormOptions` | `Omit<UseFormProps, 'resolver'>` | ❌ | Other `useForm` options (defaultValues, mode, etc.) — `resolver` must not be passed |

    **Returns:** `UseFormReturn<FieldsToObject<TFieldValues>, TContext, TTransformedValues>`

    **Example:**
    ```tsx
    const form = useZormy({
      fields: [NameField, EmailField],
      defaultValues: { name: "", email: "" },
      mode: "onChange",
    });
    <Form methods={form} onSubmit={form.handleSubmit(handleSubmit)}>
      <NameField />
      <EmailField />
    </Form>
    ```

    ## Resolvers

    ### `zormyResolver({ fields })`

    Creates a resolver for react-hook-form based on an array of fields. Supports flat and nested schemas (dot keys, e.g., `"user.email"`). Dynamic schemas (function receiving `formValues`) are evaluated at validation time.

    | Property | Type | Required | Description |
    |-----------|------|----------|------------|
    | `fields` | `readonly FieldComponentBase[]` | ✅ | Array of field components |

    **Returns:** `Resolver<FieldsToObject<Fields>>`

    **Example:**
    ```tsx
    const resolver = zormyResolver({
      fields: [NameField, EmailField]
    });

    const form = useForm({
      resolver,
      defaultValues: { name: "", email: "" }
    });
    ```

    ## Wizards

    ### `useWizard(args)`

    Hook to create and manage a multi-step form wizard.

    **Arguments:**

    | Property | Type | Required | Description |
    |-----------|------|----------|------------|
    | `steps` | `readonly string[]` | ✅ | Array of wizard steps |
    | `fields` | `StepFieldsMap<Steps>` | ✅ | Mapping of steps to fields |
    | `defaultValues` | `WizardFormData \| (() => WizardFormData) \| (() => Promise<WizardFormData>)` | ❌ | Default values (object, sync function, or async function) |
    | `onSubmit` | `(data: WizardFormValues) => void` | ❌ | Callback when the form is submitted (last step) |
    | `onStepSubmit` | `(data: WizardFormData, step: Step) => void` | ❌ | Callback when a step is submitted |
    | `initialStep` | `Steps[number]` | ❌ | Initial step (default: first step) |
    | `mode` | `"onChange" \| "onBlur" \| "onSubmit" \| "onTouched" \| "all"` | ❌ | react-hook-form validation mode |
    | `controlledStep` | `Steps[number]` | ❌ | Externally controlled step (e.g., URL query params) |
    | `onStepChange` | `(args) => void` | ❌ | Callback when step changes |
    | `autoSave` | `(args) => Promise<void>` | ❌ | Auto save: automatically saves when changing steps |
    | `shouldIncludeStep` | `(step, formValues) => boolean` | ❌ | Function to filter conditional steps |

    **Returns:** `UseWizardFormReturn<FormData, Steps> & { autoSave?, getFieldComponentsForStep }`

    ### `createWizardConfig(config)`

    Helper function to create a wizard configuration with proper type inference.

    | Property | Type | Required | Description |
    |-----------|------|----------|------------|
    | `steps` | `readonly string[]` | ✅ | Array of steps |
    | `fields` | `StepFieldsMap<Steps>` | ✅ | Mapping of steps to fields |
    | `shouldIncludeStep` | `(step, formValues) => boolean` | ❌ | Function to filter steps |

    **Returns:** `WizardConfig<Steps, TStepFieldsMap>`

    ### `createWizardComponents(config)`

    Creates typed Wizard and Step components based on a wizard configuration.

    | Parameter | Type | Description |
    |-----------|------|------------|
    | `config` | `WizardConfig<Steps, TStepFieldsMap>` | Wizard configuration created with `createWizardConfig` |

    **Returns:** `{ Wizard, Step }` - Typed components

    ### `WizardProvider`

    Provider that supplies the wizard context to child components.

    | Property | Type | Required | Description |
    |-----------|------|----------|------------|
    | `value` | `UseWizardFormReturn & { autoSave? }` | ✅ | Wizard context value |
    | `children` | `ReactNode` | ✅ | Child components |

    ### `useWizardContext<TConfig>()`

    Hook to access the wizard context.

    **Returns:** Typed wizard context

    ### `useAutoSaveContext()`

    Hook to access autoSave from the wizard context.

    **Returns:** `UseAutoSaveReturn`

    ## Types

    ### `FieldsToObject<Fields>`

    Type inferred from form values based on an array of fields. Used by the resolver and `useForm`.

    ```tsx
    type FieldsToObject<Fields extends readonly FieldComponentBase[]>
    ```

    ### `FieldKey`, `FieldValue`

    Utility types for field keys and values (exported from the package).

    ### `FieldComponent<Key, Schema, Props>`

    Typed field component returned by `field(key).schema(...).render(...)`.

    ### `ExtractWizardFormValues<TStepFieldsMap>`

    Wizard form values inferred from the step mapping (nested structure).

    ### `ExtractWizardFormData<TStepFieldsMap>`

    Wizard form data (partial values, flat or nested).

    ### `Dependency`

    Type for field dependencies: `FieldComponent`, string (field name), or lazy function returning a field.

    ### `AutoSaveStatus`

    Auto save status: `"idle" | "saving" | "saved" | "error"`.

## React Hook Form Integrations

Zormy exports some useful types and components from react-hook-form:

### `Controller`

react-hook-form component to control uncontrolled components or UI libraries.

**Example:**

```tsx
import { Controller } from "zormy";

<Controller
	control={control}
	name="fieldName"
	render={({ field }) => <CustomInput {...field} />}
/>;
```

### `SubmitHandler<TFieldValues>`

Type for form submit handlers.

**Example:**

```tsx
import type { SubmitHandler } from "zormy";

const handleSubmit: SubmitHandler<FormData> = (data) => {
	console.log(data);
};
```

### `FormProvider`

react-hook-form provider. Also exported directly from Zormy for convenience.

**Note:** For most cases, use the `<Form>` component which already provides `FormProvider` automatically.
