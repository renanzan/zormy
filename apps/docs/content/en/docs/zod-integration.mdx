# Zod Integration

How Zod rules translate into UI validation errors in Zormy.

<Callout type="info" emoji="✅">
	Zormy uses Zod as the foundation for validation. Each field can have a Zod schema that defines
	type, rules, and error messages.
</Callout>

## Overview

Zormy uses Zod as the foundation for validation. Each field can have a Zod schema that defines:

- **Expected data type** - String, number, boolean, etc.
- **Validation rules** - Min, max, email, regex, etc.
- **Custom error messages** - Custom messages for each rule

## Static Schemas

Static schemas are defined once and do not change based on other fields:

### Common Zod Rules

| Zod Rule                | Validation                   | Example                                       |
| ----------------------- | ---------------------------- | --------------------------------------------- |
| `.min(n, msg?)`         | Minimum value (string/array) | `z.string().min(3)`                           |
| `.max(n, msg?)`         | Maximum value (string/array) | `z.string().max(100)`                         |
| `.email(msg?)`          | Email format                 | `z.string().email()`                          |
| `.url(msg?)`            | URL format                   | `z.string().url()`                            |
| `.regex(pattern, msg?)` | Regex pattern                | `z.string().regex(/^\d+$/)`                   |
| `.refine(fn, msg?)`     | Custom validation            | `z.string().refine(val => val.includes("@"))` |
| `.optional()`           | Optional field               | `z.string().optional()`                       |
| `.nullable()`           | Allows null                  | `z.string().nullable()`                       |
| `.default(value)`       | Default value                | `z.string().default("")`                      |

## Dynamic Schemas

Dynamic schemas change based on values from other fields. Use a function that receives `formValues`:

```tsx
const PasswordField = field("password")
	.dependsOn(HasPasswordField)
	.schema((formValues) => {
		const hasPassword = formValues?.hasPassword;
		if (hasPassword) {
			return z.string().min(8, "Password must have at least 8 characters");
		}
		return z.string().optional();
	})
	.render(({ register, fieldState }) => (
		<div>
			<input type="password" {...register()} />
			{fieldState.error && <span>{fieldState.error.message}</span>}
		</div>
	));
```

## Error Messages

### Default Zod Messages

If you do not provide a custom message, Zod uses default messages:

```tsx
// Without custom message
z.string().min(3);
// Error: "String must contain at least 3 character(s)"

// With custom message
z.string().min(3, "Name must have at least 3 characters");
// Error: "Name must have at least 3 characters"
```

### Custom Messages per Rule

You can customize messages for each rule:

```tsx
const EmailField = field("email")
	.schema(z.string().min(1, "Email is required").email("Invalid email"))
	.render(({ register, fieldState }) => (
		<div>
			<input type="email" {...register()} />
			{fieldState.error && <span>{fieldState.error.message}</span>}
		</div>
	));
```

## Error Types

`fieldState.error` contains information about the validation error:

```tsx
type FieldError = {
	message: string; // Error message
	type: string; // Error type (e.g., "too_small", "invalid_string")
	// ... other type-specific properties
};
```

### Common Error Types

| Type             | When It Occurs             | Example                                  |
| ---------------- | -------------------------- | ---------------------------------------- |
| `too_small`      | Value smaller than minimum | `z.string().min(3)` with "ab"            |
| `too_big`        | Value larger than maximum  | `z.string().max(10)` with "abcdefghijk"  |
| `invalid_string` | Invalid format             | `z.string().email()` with "not-an-email" |
| `invalid_type`   | Incorrect type             | `z.string()` with `123`                  |
| `required`       | Required field             | `z.string()` with `undefined`            |

## Real-Time Validation

Validation mode is controlled by the `mode` of `useForm` or `useWizard`:

```tsx
const form = useForm({
	resolver: zormyResolver({ fields: [NameField] }),
	mode: "onChange", // Validates on every change
	// mode: "onBlur"   // Validates on blur
	// mode: "onSubmit" // Validates only on submit
});
```

## Cross-Field Validation

For validations that depend on multiple fields, use `.refine()` or `.superRefine()`:

```tsx
const PasswordField = field("password")
	.schema(z.string().min(8))
	.render(({ register }) => <input type="password" {...register()} />);

const ConfirmPasswordField = field("confirmPassword")
	.dependsOn(PasswordField)
	.schema((formValues) => {
		return z
			.string()
			.min(8)
			.refine((val) => val === formValues?.password, { message: "Passwords do not match" });
	})
	.render(({ register, fieldState }) => (
		<div>
			<input type="password" {...register()} />
			{fieldState.error && <span>{fieldState.error.message}</span>}
		</div>
	));
```

## Asynchronous Validation

`zormyResolver` uses `zodResolver` from @hookform/resolvers, which supports schemas with asynchronous `.refine()` or `.superRefine()` (returning a `Promise`). For asynchronous validations (e.g., checking if an email already exists), use `.refine()` with an async function:

```tsx
const EmailField = field("email")
	.schema(
		z
			.string()
			.email("Invalid email")
			.refine(
				async (email) => {
					const exists = await checkEmailExists(email);
					return !exists;
				},
				{ message: "Email is already in use" }
			)
	)
	.render(({ register, fieldState }) => (
		<div>
			<input type="email" {...register()} />
			{fieldState.error && <span>{fieldState.error.message}</span>}
		</div>
	));
```

## Transformations

Zod allows transforming values before validation:

```tsx
const PhoneField = field("phone")
	.schema(
		z
			.string()
			.transform((val) => val.replace(/\D/g, "")) // Remove non-numeric characters
			.refine((val) => val.length === 11, "Phone number must have 11 digits")
	)
	.render(({ register }) => <input {...register()} />);
```

## Nested Schemas

For nested fields, Zormy automatically creates nested schemas:

```tsx
const UserNameField = field("user.name")
	.schema(z.string().min(3))
	.render(({ register }) => <input {...register()} />);

// The resulting schema will be:
// z.object({
//   user: z.object({
//     name: z.string().min(3)
//   })
// })
```

## Practical Examples

### CPF Validation

```tsx
const CPFField = field("cpf")
	.schema(
		z
			.string()
			.regex(/^\d{11}$/, "CPF must have 11 digits")
			.refine(
				(cpf) => {
					// CPF validation logic
					return validateCPF(cpf);
				},
				{ message: "Invalid CPF" }
			)
	)
	.render(({ register, fieldState }) => (
		<div>
			<input {...register()} />
			{fieldState.error && <span>{fieldState.error.message}</span>}
		</div>
	));
```

### Conditional Validation

```tsx
const AgeField = field("age")
	.schema(z.number().min(0).max(120))
	.render(({ register }) => <input type="number" {...register()} />);

const DriverLicenseField = field("hasDriverLicense")
	.dependsOn(AgeField)
	.schema((formValues) => {
		const age = formValues?.age;
		if (age && age >= 18) {
			return z.boolean();
		}
		return z.boolean().optional();
	})
	.render(({ register, watch }) => {
		const age = watch("age");
		if (!age || age < 18) return null;

		return (
			<div>
				<label>
					<input type="checkbox" {...register()} />
					Do you have a driver's license?
				</label>
			</div>
		);
	});
```
